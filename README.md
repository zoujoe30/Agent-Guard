# Agent Guard

当前版本：0.3.20 build31。修复密码认证超时后实体鼠标持续生效：认证输入仅限可信系统弹窗，结束时立即撤销放行，等待安全输入退出后恢复托管；恢复异常时不再放行全部实体输入。保留键盘背光托管、显示偏好和快捷键功能。

Agent Guard 是一个独立的 macOS 菜单栏应用，用于在 Agent 操作当前桌面时阻止现场人员使用实体键盘、鼠标和触控板。

历史 0.3.13（构建 24）：新增按设备UUID排除外屏托管，以及旧恢复记录的安全迁移。上一版0.3.12：修复电视关机时认证阻塞与异常恢复空格拦截，166项自动检查通过；新增独立显示恢复重试入口。0.3.12已完成本机安装、签名复核与实体认证解除验证，详见 [验证记录](VALIDATION-0.3.12.md)。以下本机熄屏与认证实测属于0.3.10基线：2026-10-11 已完成本地安装、签名复核及本机实测：熄屏期间 Agent GUI 操作、实体空格唤醒与认证、主进程异常退出后的显示恢复均通过。120 项自动检查通过。正式安装包仍需 Developer ID 签名与 Apple 公证，源码同步不代表正式 Release 发布。

## 0.3.13：按设备排除外屏托管

可在本机配置明确排除的外屏UUID。被排除的电视不参与软断开、重连或热插拔健康检查；它关机时不阻塞下一轮托管，开机也不触发“新增外屏”恢复异常。Mac内屏与其余受管外屏保持原有逻辑。菜单会显示已排除的外屏数量。

已有恢复记录含被排除外屏时，在进程/会话核验及恢复锁内完整归档原记录至`excluded-recovery`，再原子保存仅含受管外屏的恢复记录；核验内屏和其余外屏恢复成功后才清活动记录。归档或保存失败时保留恢复信息并拒绝新托管。主程序与独立恢复进程共用同一排除与归档规则。

配置键为UserDefaults域`com.local.agentguard`中的`com.local.agentguard.excluded-display-uuids`字符串数组。只匹配有效且非零的精确UUID，不按设备编号或型号排除。配置应在未托管时修改，并重新启动应用。本机设备身份保存在本机设置，不写入源码。

## 当前交互

1. 打开 `Agent Guard.app`。
2. 按实体键盘的 `右 Command + G` 直接进入托管；也可点击菜单栏盾牌图标，选择“进入 Agent 托管模式”。左 `Command + G` 保持系统和软件原有功能；快捷键只能进入托管，不能解除托管。系统安全输入开启或输入监听恢复失败时，拒绝进入托管。
3. 托管期间默认并固定防止电脑休眠；显示方式在“保持常亮”和“托管黑屏”之间二选一，默认保持常亮，选择会保留到下次启动。
   切换显示方式后菜单会继续保持打开；点击菜单外部会正常关闭。
4. 实体输入被拦截；软件合成的 Agent 输入继续放行。
5. 按实体空格键，系统弹出 Touch ID／密码验证。
6. 验证期间 Agent 合成输入被冻结，实体输入只用于置顶的系统认证窗口，最多 10 秒。
7. 验证成功后退出托管模式并释放电源断言；失败或超时后，监听与显示恢复检查通过才继续托管，恢复失败则进入“托管恢复异常”。

## Agent 控制

安装后，AI Agent 可以通过本机命令切换两种显示方式：

```sh
agent-guard status
agent-guard display visible
agent-guard display blackout
```

- `status` 返回当前托管状态和显示方式，例如 `guard=guarding display=blackout`。
- `display visible` 切换为保持常亮。
- `display blackout` 切换为托管黑屏；只有处于托管状态时才会实际压暗显示器。
- 控制接口仅接受当前 macOS 登录会话内的本地请求，不开放进入、退出或解除托管命令。Agent 可以改变显示方式，但不能借此绕过 Touch ID／密码。
- 系统认证窗口显示期间不允许切换显示方式，命令会明确失败。

## 电源策略

- 托管期间固定使用 macOS 电源断言阻止电脑和显示器空闲休眠，不提供关闭选项。
- “保持常亮”和“托管黑屏”二选一，默认保持常亮。
- “托管黑屏”不会触发 macOS 显示器睡眠：MacBook 内屏保持在线、背光降到 0；外屏软断开后由显示器进入无信号待机。GUI Agent 使用内屏桌面，外屏窗口会临时迁移。恢复后 macOS 会重新连接外屏；本机单次测试的原有窗口全部恢复，但不保证所有应用、Spaces 或托管期间新开窗口均原样恢复。
- 按实体空格键时先恢复进入托管前的内屏亮度并重新连接外屏，再开始 Touch ID／密码验证。验证失败或超时后重新黑屏；成功解除、主动退出托管或退出应用时恢复原显示状态。
- 内屏亮度控制和外屏软断开使用 macOS 未公开系统接口；不使用 DDC 电源指令。需要内屏在线、非镜像外屏及可识别显示器身份。系统升级可能导致接口失效；软断开失败会回滚，并保留尚未完成的恢复记录。
- 退出托管模式或退出应用后，Agent Guard 会释放全部电源断言，恢复 macOS 原有休眠设置。
- 这些选项只在托管期间生效，不会永久修改系统电源配置。

## 0.3.9 安全输入保护（历史）

- 进入托管前检查系统安全输入；开启时拒绝进入并显示可获取的占用应用或进程。所有入口共用该检查。
- 托管期间约每 0.5 秒检查安全输入和监听健康，主线程繁忙时检测可能延迟。发现异常后恢复显示并进入 `recoveryFailed`，不会继续表示正常托管，也不会自动解除。
- 恢复异常时放行全部实体输入（包括空格）以访问菜单，继续拦截可识别的 Agent 合成输入；菜单验证解除不再以键盘监听健康或外屏恢复成功作为前提。若系统监听本身失效，无法保证输入拦截。
- 身份验证期间暂停周期检查，避免把系统密码验证所需的安全输入当作新故障；认证失败或超时后重新检查，安全输入仍开启时保持异常状态，不重新黑屏。
- 切换黑屏前同样检查安全输入。此保护不改变其他应用的安全输入设置、不自动切换焦点，也不能证明所有未知情况下键盘事件一定可达。

回归测试：`Tests/SecureInputRegression/run.sh` 编译实际控制器和输入策略，使用无副作用替身验证准入、运行中故障、认证恢复、黑屏前状态变化及监测定时器生命周期，不操作真实输入、显示或系统认证。新增 53 项回归检查及原有 26 项自动测试均通过，共 79 项；本地构建和签名校验通过。0.3.9 尚未替换本机安装版，实体键鼠、空格和 Touch ID 的安装后验收待完成，正式 GitHub Release 未发布。

## 0.3.8 输入监听恢复改进（历史）

- 进入托管、进入验证、验证失败后恢复托管，以及托管期间切换黑屏前，检查事件端口、Run Loop Source 的有效性和监听启用状态。禁用时先恢复并读回；仍失败则清理并重建一次，最终失败时拒绝进入托管或黑屏。
- 收到系统禁用监听通知后执行同样的恢复检查，丢弃旧监听器遗留的恢复任务。运行中恢复失败时取消正在进行的验证、尝试恢复显示，并进入“托管恢复异常”状态；CLI 返回 `guard=recoveryFailed`，不会把异常当作验证成功。0.3.8 通过菜单重试验证前必须先恢复监听；0.3.9 已移除此异常恢复路径的前置要求。
- 系统统一日志的 `com.local.agentguard` 子系统记录监听创建、禁用、恢复结果和托管状态变化，不记录按键内容。
- 上述检查验证监听对象有效且已启用，不能证明安全输入或系统锁屏期间键盘事件可达；0.3.8 没有实现系统锁屏／解锁联动或无禁用通知时的周期健康检测；0.3.9 新增的周期保护见上节。

0.3.8 当时的 26 项自动测试通过，其中包含 8 项监听恢复策略检查；安装包已通过版本、签名、内容一致性和本机启动检查，但该版实体快捷键、空格和 Touch ID 的安装后验收未完成。当前 0.3.10 验证状态见验证记录。

## 已知边界

- 这是防止现场误操作的同会话托管模式，不等同于 macOS 系统锁屏。
- 当前通过 Quartz 事件的来源 PID 判断实体输入。不同 Agent 工具可能采用不同输入注入方式，必须做真实兼容性验证。
- 如果 Agent 输入也表现为无来源 PID 的 HID 事件，它会被一并拦截，需要改为显式标记或通过 Agent Guard 转发。
- 认证期间应用只能冻结 Agent 的合成输入事件，无法通知任意第三方 Agent 暂停其任务状态机；集成方应读取后续提供的状态接口，避免把冻结期间的点击当作成功。
- 不显示遮罩，也不调用系统显示器睡眠；托管黑屏时按上文规则软断开受管外屏。

## 构建

```sh
./build-app.sh /不受文件提供器管理的绝对输出目录
./build-pkg.sh /交付目录 /交付目录/Agent\ Guard-0.3.10.zip
./test.sh  # 包含基础自测及安全输入回归
./smoke-test.sh /交付目录/Agent\ Guard-0.3.10.zip
```

要求 macOS 14 或更高版本，以及 Swift 6 工具链。

构建和测试中间产物会放在 `/private/tmp`。`build-app.sh` 要求显式指定输出目录，并按 `AppInfo.plist` 中的版本号交付不包含扩展属性的 `Agent Guard-<version>.zip`；`build-pkg.sh` 再以该 ZIP 为输入，生成把应用安装到 `/Applications` 的 `Agent Guard-<version>.pkg`。不要直接把未压缩 App 输出到 Desktop 或其他会自动附加 FinderInfo 的文件提供器目录，否则代码签名可能随后失效。

构建前必须通过 `AGENT_GUARD_SIGNING_IDENTITY` 指定钥匙串中可用的稳定代码签名身份；未配置时构建会安全失败。请保持自己的签名身份稳定，避免升级后辅助功能和输入监控权限失效。此仓库不附带签名证书或私钥。

给普通用户分发时优先使用 PKG：双击后按安装器提示继续，并通过 Touch ID 或管理员密码确认安装。普通本地构建仍使用本地代码签名身份，且 `build-pkg.sh` 在没有 `AGENT_GUARD_INSTALLER_SIGNING_IDENTITY` 时会生成未签名 PKG；正式 GitHub Release 则必须经过 Developer ID Application、Developer ID Installer 和 Apple 公证。PKG 只负责把应用安装到 `/Applications`，不能代替用户授予“辅助功能”和“输入监控”权限。ZIP 保留为手动安装备用包。

## 正式签名、公证与 GitHub Release

`release.sh` 执行完整的正式交付链路：

1. 以 `arm64` 和 `x86_64` 构建通用 App，并使用 Developer ID Application、硬化运行时和可信时间戳签名。
2. 将 App ZIP 提交 Apple 公证；成功后把公证票据 staple 到 App，并重新生成 ZIP。
3. 从已 staple 的 App 构建 PKG，使用 Developer ID Installer 签名，再次提交公证并 staple PKG。
4. 使用 `codesign`、`spctl`、`pkgutil` 和 `stapler validate` 验证交付物，并生成 SHA-256 校验和。

本地运行时可使用钥匙串中保存的 notarytool profile：

```sh
export AGENT_GUARD_SIGNING_IDENTITY='Developer ID Application: Example (TEAMID)'
export AGENT_GUARD_INSTALLER_SIGNING_IDENTITY='Developer ID Installer: Example (TEAMID)'
export AGENT_GUARD_NOTARY_PROFILE='agent-guard-notary'
./release.sh /不受文件提供器管理的绝对输出目录
```

`.github/workflows/release.yml` 会在推送 `v*` 标签时运行同一链路，也可以对一个已存在的标签手动运行。仓库需要配置以下 Actions secrets：

- `DEVELOPER_ID_APPLICATION_P12`
- `DEVELOPER_ID_APPLICATION_PASSWORD`
- `DEVELOPER_ID_INSTALLER_P12`
- `DEVELOPER_ID_INSTALLER_PASSWORD`
- `SIGNING_KEYCHAIN_PASSWORD`
- `APPLE_API_PRIVATE_KEY`
- `APPLE_API_KEY_ID`
- `APPLE_API_ISSUER_ID`

两个 P12 secret 均保存为 base64 文本；`APPLE_API_PRIVATE_KEY` 保存 App Store Connect API 私钥的完整 `.p8` 内容。标签必须与 `AppInfo.plist` 版本严格对应，例如版本 `0.3.9` 使用标签 `v0.3.9`。任何签名、公证、staple 或 Gatekeeper 校验失败都会阻止 GitHub Release 创建。

## 0.3.10（build 21）：外屏软断开

- 黑屏时先软断开外屏，最后降低内屏背光；恢复时先亮起内屏，再按显示器 UUID 重连外屏。不会主动改变分辨率、刷新率或应用窗口位置。
- 断开前原子保存恢复记录到 `~/Library/Application Support/Agent Guard/display-recovery.json`；重连失败保留记录，进入恢复异常状态，可通过菜单重试。
- 独立恢复进程监测主进程管道。主进程异常退出后尝试恢复显示；记录仍未恢复时，下次启动继续重试。异常退出意味着输入拦截已停止，不能视为继续托管。
- 外屏断开使用应用生命周期配置作为额外恢复保障。托管期间检测到外屏重新上线、新外屏、内屏离线或独立恢复进程停止时，停止黑屏并进入恢复异常状态，不盲目反复断开。
- 单次原型实测已确认 Mi Monitor 直连可彻底熄灭背光，重连后 2560×1440 120 Hz、11 个普通窗口位置均恢复。产品集成验收见随包验证记录，不以原型代替完整托管验收。
- `Tests/DisplayRecoveryRegression/run.sh` 使用无硬件副作用替身验证恢复顺序、部分失败回滚、记录保留、重试、进程保护和并发 token 隔离。

## 0.3.12（build23）：关机电视不再卡住输入解除

- 恢复异常时，所有实体输入（含空格、长按、修饰键组合）正常放行，空格不再反复触发认证；从菜单“立即验证解除”重试。
- 外屏恢复失败不再阻止 Touch ID／密码认证。认证成功后解除输入托管、释放电源断言；未恢复的电视仍保留恢复记录，并明确提示显示恢复待完成。
- 电视开机后可点击“重试显示恢复（电视开机后）”。恢复失败不重新锁住输入。未完成的恢复记录会阻止新一轮黑屏，以免覆盖原有恢复信息；重新开机并完成显示恢复后即可继续托管。
- 认证取消或超时后，原本处于异常恢复、或本次显示恢复失败的会话保持异常状态，不重新黑屏。正常托管的空格认证流程保留。
- 系统拒绝显示配置与配置成功但在线状态未核验分开报告，包含显示器身份和状态。不会将关机电视标记为已恢复，也不丢弃同启动恢复记录。
